# Architecture

```
┌──────────────────────────────── Tauri app ────────────────────────────────┐
│ MAIN WEBVIEW (ui/: React + CodeMirror 6)                                  │
│  Editor · Explorer · Outline · Search · Components palette · Problems     │
│        │  invoke(...) / events  (capabilities: core:default, dialog:open) │
├────────▼──────────────────────────────────────────────────────────────────┤
│ RUST CORE                                                                 │
│  src-tauri  commands.rs ─ watcher.rs (notify) ─ preview_protocol.rs       │
│  mdx-workspace  config · file walk (ignore) · search · atomic save        │
│     └─ analyze(): mdx-syntax ─► mdx-intel (components, frontmatter, links)│
│  mdx-compile   mdxjs: mdast → hast ─► [Rust transforms] ─► SWC → ESM      │
├──────────────────────┬────────────────────────────────────────────────────┤
│ PREVIEW IFRAME       │ src = mdxpreview://localhost/ (own origin)          │
│ (preview-runtime/)   │ sandbox="allow-scripts", strict CSP, no IPC        │
│  blob-module shims for react / react/jsx-runtime / team package           │
│  ErrorBoundary → postMessage errors back                                  │
└──────────────────────┴────────────────────────────────────────────────────┘
```

## Edit → preview loop

1. CodeMirror change → `App.refresh()` debounced 150 ms.
2. In parallel over IPC:
   - `analyze(path, source)` → `DocumentAnalysis` (outline, links, components, frontmatter, diagnostics)
   - `compile_preview(path, source)` → ESM string, or a compile diagnostic
3. The UI posts `{type: "render", code}` to the iframe. The runtime rewrites bare imports to blob shims, `import()`s the module and renders `<MDXContent components={team + builtins}>`.
4. Runtime errors come back as `{type: "error"}` and show in Problems.

Why the iframe and not the main webview? **MDX is JavaScript.** Docs run arbitrary code, so they get an opaque origin with no Tauri capabilities. The only server they can reach is `mdxpreview://`, which exposes the runtime, the team bundle/CSS, and image/media files from the workspace. It never exposes `.mdx` or source files.

## Analysis pipeline

| Stage | Crate | Notes |
|---|---|---|
| Parse | `mdx-syntax` | markdown-rs with MDX + GFM + frontmatter; big-stack thread so pathological nesting can't crash the app; accepts any ESM (SWC validates it at compile time) |
| Components | `mdx-intel::manifest` | skips lowercase HTML, `{...spread}`, and names bound by `import` |
| Frontmatter | `mdx-intel::frontmatter` | YAML/TOML → JSON → `jsonschema`; schema chosen by glob in `config.toml` |
| Links | `mdx-intel::links` | relative + root-relative; `.mdx`/`.md`/`index.mdx` fallbacks; anchors via GitHub slugger; never resolves outside the workspace |
| Compile | `mdx-compile` | same stages as `mdxjs::compile`, with a hook between hast and SWC for Rust "rehype plugins" |

Positions: Rust uses 1-based line/column and **UTF-8 byte offsets**. `ui/src/editor/positions.ts` converts them to CodeMirror's UTF-16 positions.

## Team configuration (`.mdx-ide/` in the docs repo)

```
.mdx-ide/
  config.toml                 content/static dirs, schemas, preview, lint toggles
  component-manifest.json     generated by sidecars/manifest-gen
  schemas/*.schema.json       frontmatter JSON Schemas
  templates/*.mdx             new-document templates (v1)
```

Changes under `.mdx-ide/` hot-reload through the file watcher.

## Risks and mitigations

- **WebKitGTK on Linux** is the slowest and quirkiest webview. The preview is isolated in an iframe and CodeMirror virtualises rendering. Test early on the team's real distros and GPUs (`WEBKIT_DISABLE_DMABUF_RENDERER=1` works around NVIDIA/Wayland crashes). Plan the Tauri 3 CEF runtime switch as one release decision once it's stable.
- **Preview ≠ production** when the site relies on remark/rehype plugins. Port the common ones as Rust transforms in `mdx-compile`, and add a "site-accurate" mode that compiles with `@mdx-js/mdx` + the site's plugins in a Node sidecar.
- **Components with side effects** (router hooks, data fetching, `window`) break in the preview. Add mock providers in `preview-runtime` and an optional per-component preview stub in the manifest.
- **Pasted Markdown** often becomes invalid MDX (`<!-- -->`, `{`, `<`). Add a "fix pasted Markdown" quick fix.
- **Tooling churn**: the MDX language server and TS content-mapper are in flux. Component intelligence is owned here (manifest), so those can be added later as optional sidecars.
